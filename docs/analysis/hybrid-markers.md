# Гибрид B: правила и предсказания (фиксируется ДО замеров)

Правила составлены после просмотра eval_set_v1, поэтому слепыми не являются.
Опираются на слова из ответа заказчика («за», «в пользу», «выгодоприобретатель»)
и на гипотезу А. После прогона правила не меняются: если B проиграет, это результат.

## Правила (сверху вниз, срабатывает первое)
1. Отрицание: решение `NEGATED` из существующей логики `/classify`
   (`NEGATION_WINDOW` = 20, не меняется). Ответ `no`.
2. Сильный маркер без имени: `выгодоприобретател*` или `треть* лиц*`. Ответ `yes`.
3. Предлог «за» / «за счёт» / «в пользу» / «в интересах», затем не более двух слов,
   затем PER-спан Natasha. Ответ `yes`. «За» без PER ничего не значит.
4. Иначе решение семантики `/classify` при пороге 0,5.
   Правила 2 и 3 работают и для фраз, остановленных gate (`GATED`). В этом их смысл.
   Имя для `yes` берётся из `/extract-name` как есть.

## Варианты
A_0.5, A_0.75 (текущий классификатор), B_0.5 (гибрид, порог 0,5 в правиле 4).

## Метрики
Precision, recall, F1 по `yes`; точное совпадение имени (регистр, е/ё игнорируются);
строки 34 и 35 (интерпретация) считаются отдельно. Разрезы: категория, `near_*` / «чистые»,
«прошло gate» / «не прошло». Оцениваются 28 строк: 17 `yes` + 11 `no`
(без `unclear` и `self_name`). Всегда указываются счётчики, не только проценты.

## Предсказания (по коду и тексту набора)
- P1. A при любом пороге: gate не пропускает `yes`-строки 1, 5, 30, 32, 35.
  Потолок recall A = 12/17 = 70,6%.
- P2. Строки 21, 22, 23: `NEGATED` → `no` (верно) в A и B.
- P3. Строка 8: «не» в 6 символах от «лицо» → `NEGATED` → `no`. Это ошибка (метка `yes`)
  и в A, и в B. Строка 24 получит `no` по той же причине (верно случайно).
- P4. B возвращает строки 1, 5, 30, 32, 35, только если NER находит PER.
  Для инициалов (30, 32) и «Степановича Андрея» (35) исход не предсказываю.
- P5. На 11 строках `no` B не добавляет ложных срабатываний
  (в них нет PER после предлога; «в пользу ИФНС» — ORG, а не PER).
  Это самое слабое предсказание, зависит от NER.
- P6. A_0.75 покажет recall не выше A_0.5 (ранее на другом наборе порог 0,75 резко снижал recall).

## Критерий вывода (до замеров)
- B считается лучше A_0.5, если исправляет не менее 2 `yes`-строк и добавляет не более 1 ложного срабатывания.
  Меньшая разница на 28 строках ничего не доказывает.
- Выводы приводятся отдельно по всем строкам и по «чистым» (без `near_*`).
- Любое изменение правил по итогам этого прогона проверяется только на новом наборе,
  размеченном до замеров.
