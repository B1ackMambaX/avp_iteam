## Что показали замеры помимо предсказаний

Решение «yes» и извлечённое имя расходятся. Ошибки имени у B (9 из 13 верно):
- строки 3 и 28: имя «Опл» и «Превод», хотя ФИО в тексте есть. Гипотеза: `/extract-name` берёт первый PER-спан (`marker_position=0`), а правило 3 в скрипте использует спан после предлога. Нужно проверить по текстам.
- строка 27: имя пустое (капс), решение верное.
- строка 30: «Зотов Т.М.» вместо «Зотова Т.М.» (женская фамилия с инициалами). Причина не установлена.
- строки 34, 35 (интерпретация «отчество + имя»): 0 из 2, считаются отдельно, выводов не делаем.

self_name: классификатор B пропускает строки 13 и 15 (в A только 13). Снимает их сверка в Java. Скрипт эту сверку не вызывает, поэтому здесь проверен только классификатор.

## Что цифры не доказывают

- Правило 3 («за» + PER) формализует то же определение, по которому размечен набор («за» значит третье лицо только вместе с именем). Часть успеха B заложена в определении. Измерено, насколько хорошо NER находит PER после предлога, а не то, что определение совпадает с реальностью.
- Строк no всего 11. Паттерн «за + услуга + ФИО» и ложные PER на длинных назначениях платежа набор почти не проверяет.
- Набор уже использован: правила гибрида после этого не менять. Любое изменение проверяется на новом наборе, размеченном до замеров.
- Это замер классификатора на отдельных фразах, не точность маппинга. Влияние на демо не измерялось.

## Вывод

При интеграции имя берётся из спана правила 3, а не отдельным вызовом /extract-name. Окно отрицания в символах не отличает отрицание рядом от отрицания в соседней клаузе, оценим на v2.
## Диагностика по строкам 3, 8, 23, 28, 30

- **Строки 3 и 28** (`Опл. обучения в интересах Крылова…`, `Превод за трете лицо Савельева…`). Первое слово с заглавной буквы (сокращение и опечатка) похоже на PER для Natasha. Гипотеза: `/extract-name` берёт первый PER-спан (`marker_position=0`), а правило 3 в скрипте берёт спан после предлога. Поэтому решение верное, а имя «Опл» и «Превод». Для интеграции это значит, что имя нужно брать из спана, найденного правилом 3.
- **Строка 23** (`Отсутствует привлечение третьих лиц по договору`). Окно ±20 не захватило «отсутствует» (начинается с 0, а «третьих» с 24). NEGATED не сработал, а правило 2 увидело «третьих лиц» и вернуло yes. Это единственный fp.
- **Строка 30** (`Оплата за Зотову Т.М.`). Форма «Зотову» неоднозначна. Нормализатор не определяет род по одной фамилии с инициалами, остаётся запасной путь Natasha. Это ограничение, а не опечатка в коде. Вопрос «как сопоставлять фамилию+инициалы с `contract_parties`» нужно задать второму бэку.

Результат `scratch_spans.py` подтверждает/опровергает гипотезу про первый PER-спан.
