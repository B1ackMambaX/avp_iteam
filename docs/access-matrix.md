# Матрица прав и ролей

## 1. Назначение документа

Данная матрица описывает минимальную ролевую модель доступа для MVP системы автоматической привязки банковских операций к договорам.

В системе предусмотрены три роли:

- **Читатель (`READER`)** — просмотр данных и экспорт доступной информации.
- **Редактор (`EDITOR`)** — права Читателя, выполнение бизнес-действий с операциями, клиентами и договорами.
- **Администратор (`ADMIN`)** — права Редактора, управление пользователями, системными настройками и служебными действиями.

Роли пользователей хранятся в таблице `app_user` (миграция V8), в поле `role`. В рамках данной модели каждому пользователю назначается одна роль.

**Принцип доступа:** разрешение на действие не отменяет бизнес-ограничения и проверки согласованности данных. Ограничения применяются ко всем ролям, включая Администратора.

## 2. Условные обозначения

- `+` — действие доступно с учётом общих бизнес-правил.
- `−` — действие недоступно.
- `+*` — действие доступно с дополнительными ограничениями, описанными в разделе 4.

## 4. Ограничения и бизнес-правила

### 4.1. Изменение привязки и статусов операций

Редактор не имеет права произвольно изменять поле `operations.status`.

При ручном подтверждении, изменении или отмене привязки система согласованно обновляет:

- итоговую связь с договором — `contract_id`;
- статус операции — `status`;
- сведения об авторе и времени действия — `mapped_by`, `mapped_at`.

Допустимые переходы статусов и правила заполнения этих полей, включая поведение при отмене привязки, определяются отдельной спецификацией модели состояний.

Администратор может выполнять служебные переходы статусов для восстановления обработки, например при зависании операции. Такие действия не должны нарушать согласованность статуса операции, привязки к договору и связанных задач.

Право Администратора не предполагает возможность установить произвольный статус без соответствующих проверок.

### 4.2. Удаление клиента

Удаление клиента запрещено для всех ролей, если на него существуют ссылки в `contract_parties`.

Наличие дополнительных связей, блокирующих удаление клиента, должно быть проверено по актуальной схеме БД. Если такие связи существуют, они включаются в перечень ограничений.

Удаление клиента из состава сторон конкретного договора и удаление самой записи клиента являются разными действиями.

### 4.3. Удаление договора

Удаление договора запрещено для всех ролей, если на него существуют ссылки в:

- `operations`;
- `operation_mapping_candidate`.

Правило обработки записей `contract_parties` при удалении договора подлежит отдельному согласованию: они либо блокируют удаление, либо удаляются вместе с договором.

До согласования этого правила операция удаления не должна приводить к неявному удалению связанных данных.

Архивация клиентов и договоров в рамках данной версии MVP не предусмотрена.

### 4.4. Настройка параметров маппинга и парсинга

Изменение настроек доступно только Администратору.

К настраиваемым параметрам могут относиться пороги уверенности парсинга и параметры правил скоринга. Точный перечень параметров, допустимые значения и способ их изменения определяются отдельно.

Таблица `operation_mapping_candidate` хранит результаты подбора кандидатов, оценки и сработавшие правила, а не конфигурацию системы.

Место хранения настроек и наличие интерфейса для их редактирования должны быть согласованы до реализации соответствующего действия. До этого строка матрицы фиксирует распределение прав, а не наличие готового функционала.

### 4.5. Перезапуск и сброс NLP-задач

Перезапуск и сброс NLP-задач доступны только Администратору.

При выполнении действия система должна проверять текущее состояние задачи и сохранять согласованность задачи с операцией и результатами обработки.

Допустимые состояния для перезапуска, правила изменения счётчика попыток, блокировки и результатов предыдущей обработки определяются спецификацией очереди NLP.

### 4.6. Экспорт данных

Пользователь может экспортировать только те данные и поля, которые доступны ему для просмотра.

Право на экспорт не расширяет права доступа. В частности, Читатель и Редактор не могут включать в выгрузку сведения о NLP-задачах и их ошибках, недоступные им в интерфейсе.

Если для персональных данных предусмотрены дополнительные ограничения экспорта, они задаются отдельным перечнем полей и применяются ко всем способам формирования выгрузок. Такой перечень подлежит согласованию.
